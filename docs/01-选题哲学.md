# 01 · 选题哲学

## 一条内容主线

content-machine 以 Apodex 的产品能力和官网同构问题为起点。外部事件负责提供 timing、真实案例与一手证据，不能反过来定义品牌每天讲什么。

当前保留两条原创系列：

- **Design Choice**：从技术报告中的关键设计选择出发，讲清“为什么这样设计”以及它解决了什么真正困难的部分。
- **Problem Shape**：从官网同构的重型研究问题出发，再用报告、demo、benchmark 或内部案例解释 Apodex 为什么能承接。

Proof / verification 系列暂停。benchmark 只在确有新结果或必要事实核时使用，不作为日常母题。

## 终审顺序

1. 多条来源实际描述的是哪个 canonical event？
2. 事件能否匹配一个 active editorial intent？
3. 官号为什么有资格讲？
4. Apodex 当前能否处理、演示，或是否已有内部证据支持？
5. 是否与官网展示的问题形态同构？
6. 普通目标读者能否立即理解？
7. 是否有一句可带走的判断和清晰视觉论点？
8. 本期是否已经使用过同一 canonical event 或同一叙事？

垂直专业问题若没有 capability、demo、benchmark 或内部案例支撑，只能作为洞察，不进入官号原创。

## 来源与归宿

每个 canonical event 在一份日报中只能有一个 `primary_destination` 和一个
`primary_action`。不同报道只是该事件的 mentions，不会各占一个栏目。

X、Reddit、RSS、News、官方记录和 web source 都是证据角色：

- `timing_signal`：说明为什么现在讲。
- `real_case`：提供真实用户问题或后果。
- `primary_record`：支撑事实与状态。
- `expert_context`：补充背景，不单独定义母题。
- `lead_only`：只用于发现线索，必须回到原始材料。

## 排除边界

默认排除：无能力支撑的垂直研究建议、学术方法论文、复现性泛叙事、泛 AI 幻觉、AI4AI、竞品 launch、匿名 Reddit 品牌案例、低 reach 互动、以及只有“新”但没有产品同构问题的材料。
