# 05 · 写作与分发 —— 选题之后

> 前四篇管到"选题 + 角度/hook 候选 + 质检"。这篇管**写作**和**分发**。
> **核心原则：写作不锁框架。** 系统已经把鉴别力前置（选题→角度→hook→事实核→质检），
> 写作是人的 taste 增量最大、框架减分最多的一步——**放开写，质量由 gate 保，不由框架保。**

## 写作（voice 起草）

**默认流程**：
1. **有 taste 的人（Selene）先出草稿**——可裸写，不套任何 voice skill。不同内容各有亮点，别塞进一个框架磨平。
2. **需要时取 1 个 voice skill 调味**（à la carte，不叠、不强制）——见下表。
3. **`产品技术专家` 核**（数字 verbatim / 红线 / claim 有一手源）。
4. **`狠编辑-X` 打分放行**（7 项 rubric + triple-translation + 算法自查三问）。

> ⚠️ **不学旧声音**：`apodex-x-official-style` 已从写作链移除（pivot 前旧帖，会限制内容+夹带作废口径）。
> 写作只学**算法**（`04-算法纪律.md` + `~/Desktop/X 渠道运营.md`）+ **红线**（RULES.md）。

**voice skill à la carte 备查表**（想调味时按栏目取一个）：

| 栏目 | 可取 | 各自擅长 |
|---|---|---|
| ①难题求解 thread | `apodex-tech-voice`(Simon) / `karpathy-explain` | 技术散文 / 把概念讲给工程师 |
| ②验证拆解 | `apodex-tech-voice` / `selene-academic-voice` | 深度论证、严格引证 |
| ③世界观 | 搬老板 blog（轻改写） | — |
| ④接话 | `selene-community-voice`（多半裸写） | 真人运营腔 |
| 大件迭代(launch) | `selene-content-sop` | 多 skill 编排流程 |

（`julian-shapiro` 不常备——偏 viral 结构，与 eddie 功能重叠、不如 eddie 聚焦。）

## 分发（repurpose：anchor → micro）

一条 anchor（通常是 thread）→ 两个方向，**人 taste 主导，狠编辑兜底**：

- **① 单推（X 内）**：从 anchor 里挑能**独立成立**的点，各自成推——每条必过 candidate isolation（有自己的 hook，不靠上下文）。走 X 算法（`04-算法纪律.md`）。
- **② LinkedIn 版**：**不是复制粘贴**，按 LinkedIn 算法重排。
  - 用 **`/linkedin-algorithm`** skill 当 LinkedIn 侧"算法脑"（dwell time / carousel vs 文字 / golden hour / 格式配比）——它是我们 X 侧算法拆解的 LinkedIn 对应物。
  - 配 LinkedIn house-style（`apodex-linkedin-official-style` 记忆，27 帖实测）——同样**只学格式/算法、去老口径、不学旧声音**。

编排本身走 `selene-content-sop` 的分发步。

## 边界

**content-machine 管到"选题 + 角度/hook 候选 + 质检兜底"；写作与分发交给人的 taste + 按需 skill + gate 兜底。** 不把写作塞进机械管线。
